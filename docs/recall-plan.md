**共享素材召回改造计划**

状态：实施中，实际进度与验证证据见[实施记录](recall-progress.md)。日期：2026-09-09。基于当前 refactor/refactor_recall 分支。

本轮目标是改进“可检索内容生成 → 向量入库 → 候选召回 → 融合排序 → 返回候选”的完整共享链路。默认相关性优先，保留两个公开业务接口的格式和调用习惯。

2026-09-09 用户补充：**以语义命中为准，同时保留语境**。词法命中仅提供补充证据，不能凭散字或标签匹配让语义无关素材成为合格候选。查询侧保留当前片段及已有前后文，素材侧检查短摘要是否脱离所属主体和场景；不能把提高字符覆盖率当作语义相关性的替代。具体相关性约束须经真实画面对照验证后实施。

共享召回边界停在有序候选集合。按用户最新授权，分段匹配增加全时间轴的均匀素材分配，避免前段提前耗尽后段候选；公开字段、ASR 对齐、任务和回调继续保留。只使用 Embedding + ES + RRF，不加入 LLM 召回或模型重排。两个接口的共享阈值当前为 0.5，详见[最新实现与验证](recall-balanced-placement-2026-09-09.md)。

**当前依据与改造目标**

| 当前实现 | 本轮目标 |
| --- | --- |
| 描述和视频摘要各自成为独立 ES 文档 | 一个素材作为顶层文档，文本块及向量作为 nested 子对象 |
| 分块无长度上限，只有去空和完全去重 | 确定性的有来源分块，限制模型输入长度，保留完整信息 |
| 名称、人工标签、模型标签未参与文本检索 | 单独建立词法字段，和描述语义检索各司其职 |
| 更新先删除旧块，再批量写新块 | 准备完整新版本后替换单个素材文档 |
| 索引状态没有有效的内容版本防护 | 内容指纹、递增修订号、每个索引构建分别记账 |
| 两路各取 100 个块，然后去重 | 两路都按不同素材计数，再按素材融合 |
| 同一个素材不同块分别命中两路，不能形成跨块融合 | 两路各自选出素材证据，在素材层融合 |
| 所有文本共用合成集得到的两个固定阈值 | 用真实标注集校准召回规则，并与索引和模型版本绑定 |
| 合成 F1@8 是主要效果依据 | 检查候选覆盖、排序、无匹配查询和两类入口的分组表现 |

**共享边界和返回契约**

公开 API 入参与出参保持不变，是本轮硬约束。适用于 POST /api/v1/assets/query 和 POST /api/v1/compat/segment-match，以及后者的任务查询结果与回调体；复用查询服务的 MCP 工具也保持现有契约。

字段名称、类型、必填/可选、默认值、校验规则与空值约定均保持；不要求调用方增加参数，不增删公开响应字段。分页规则、同步/异步状态码、错误响应结构、任务和回调格式继续沿用。候选诊断、索引版本、原始相似度与命中证据只作为内部类型或受控诊断数据，不添加到公开响应。素材命中集合、顺序及排序分数会随召回策略变化，这是本轮预期效果；既有分数字段仍表示 RRF 排名分与贡献，不改变成相似概率。

P0 固定两个接口及回调的契约用例，P3 和切换前复验。契约验收覆盖正常命中、空结果、分页、白名单、默认参数、异步受理/任务完成/回调与依赖失败；允许命中 ID 和分数变化，但不能把整个响应简单快照替换为新值后视为兼容。实施不得以增加公开字段或修改请求约定绕过内部改造。

保留一层兼容包装，使现有 searchAssets(query, eligibleAssetIds) 的两个调用点能接入新引擎。新引擎不感知 HTTP 路由、文案分段、随机策略或分页游标。

    素材查询：queryAssetsPage ───────────────────────────┐
                                                      ├→ recallAssets → 有序候选
    分段匹配：searchAssetsByDescriptionDetailed ────────┘

内部请求包含规范化查询文本、MySQL 已筛好的素材 ID 集合，以及服务端召回配置版本。候选窗口和最终业务返回条数分开：调用方需要 1 条素材，不代表引擎只获取 1 条候选。

语境改造的内部边界：直接使用业务已有 `llm.segments` 的顺序和 `group_id`，不重新分段，也不依赖顶层 `text`。当前句与前一句组成内部上下文（最多 1024 个 Unicode 字符），当前片段仍独立传入。v2 将两份向量按当前片段 0.7、上下文 0.3 混合并归一化；这是待验收的实验比例，不是已验证的语义理解能力。`assets-query` 无附加上下文时保持原始查询；公开请求和响应字段不变。v1 保留原实现作为回退路径。

v2 混合召回中，BM25 独有候选在其有限 ID 范围内补做同一阈值的向量检索，通过后才参与 RRF。词法单路仍可用于离线消融。2026-09-09 的 36 段 / 11 素材真实案例已回放，上下文传递和候选范围检查通过，但质量仍未通过验收；不能仅凭代码测试通过切换读取引擎。

内部响应保留 assetId、searchScore、keywordScore、semanticScore，并增加可选诊断：命中路、原始余弦分数、原始词法分数、两路排名、最佳证据文本及来源、索引与配置版本、候选窗口是否截断。公开 API 仍通过原适配器输出现有字段。

searchScore 和两个分项继续表示归一化的 RRF 排名分及贡献；原始相似度另外命名，不把排序分解释为匹配概率。新增诊断不进入公开响应和普通日志。

同一索引快照、查询、范围和配置，应得到稳定顺序；并列候选按 assetId 排序。近似向量检索跨索引刷新不承诺结果绝对不变。

两个入口原有的作用域、审核状态、候选白名单与已用素材排除保持在原适配层。引擎收到 eligibleAssetIds=[] 必须返回空；分段接口原有 asset_url_list=[] 或未提供时不限制指定素材的语义仍由适配层保留，两者不能混淆。旧 semantic_threshold 参数本轮保留兼容状态，不偷偷启用 0.3；它不是共享引擎的有效配置项。其废弃说明记录在接口文档中，最终接口清理另行处理。

**向量与文本入库策略**

1. 明确每类内容的检索角色。

| 内容 | 向量 | 词法 | 来源信息 |
| --- | --- | --- | --- |
| 素材 description | 是 | 是 | 人工或模型写入的当前描述 |
| 视频 timeline 摘要 | 是 | 是 | 素材内相对起止时间 |
| 独有的 visualSegments / keyMoments 摘要 | 是 | 是 | 原字段与时间；重复文本合并来源引用 |
| 素材名称、人工标签 | 首版不拼入视觉向量 | 是，支持精确字段及全文字段 | 保留标签来源与分类 |
| 模型标签、topics | 首版不拼入视觉向量 | 独立字段，权重由评测决定 | 与人工标签区分 |
| OCR | 默认关闭，可作为独立词法消融项 | 通过评测后再启用 | 不与视觉描述混成一个字段 |

不新增一次 VLM 调用生成检索摘要。沿用现有模型产物，先把已有信息组织好。模型漏描述的真实画面内容仍是本方案的上游限制，应在评测中单独归因。

兼容当前 schema_version=1 的分析结果，也允许 analysis=null：描述非空即可生成描述块。只有描述的存量素材不得被新的必填字段排除。当前无描述且分析失败的素材沿用原状态，不因重建变成可用素材。索引构建不要求媒体对象引用存在，也不改写既有 original_path 回退路径。

2. 使用确定性的分块规则。

短描述、短摘要保留完整；长文本按段落和中文句界拆分，再以与 embedding 服务一致的 tokenizer 计数。首轮实验使用目标 256 tokens、硬上限 512 tokens，长文本跨窗最多重叠 32 tokens。这些是实验起点，需先核对服务实际模型和输入上限，再用长度分布及效果决定冻结值。

不跨不同来源随意拼接。相同规范化文本可复用一次 embedding，但保留全部来源引用；不同时间出现相同摘要不能丢掉时间信息。超长原句继续按 token 边界拆分，不静默截断。设置单素材块数上限，超限明确报错并留诊断；正常数据和最长合法人工描述必须覆盖在容量测试中。

每块记录 chunkId、text、textHash、sourceRefs、tokenCount。chunkId 由分块版本、文本指纹与来源构成，避免使用会随数组插入整体漂移的序号作为唯一身份。来源时间使用素材内相对时间；父视频的绝对偏移另存，避免混淆。

3. 索引改为素材文档内含多向量。

    AssetSearchDocument
      assetId, schemaVersion, sourceRevision, contentHash, deleted
      embeddingFingerprint, chunkerVersion
      name / exactName
      humanTags / modelTags / topics
      chunks[] (nested)
        chunkId, text, textHash, sourceRefs, tokenCount, embedding

一条顶层文档对应一条现有素材记录，公开视频与个人副本仍保留不同身份，不跨用户合并。mapping 固定向量维度、cosine 度量和分析器，不允许后续首个请求自行猜测模型配置。

选择 nested 的原因：ES 8.11 支持按最近文本块为顶层素材打分，并按顶层素材产生不同候选；也支持返回最近块的 inner_hits。8.11 的向量 inner_hits 只提供最近的一块，计划不依赖新版多块能力。过滤条件使用顶层 assetId。[Elastic 8.11 nested kNN](https://www.elastic.co/guide/en/elasticsearch/reference/8.11/knn-search.html#nested-knn-search)

此方案会在更新一个块时重新索引该素材文档，因此第一阶段必须测量最大文档的写入耗时、nested 块数量与索引体积；不能只看召回改善。

4. 避免重复 embedding 和不完整更新。

首版沿用当前 bge-m3 服务，不同时更换 embedding 模型。embeddingFingerprint 包含实际模型修订标识、维度、归一化与输入预处理版本；不能仅用可被服务端重新指向的模型名称判定一致。chunkerVersion、mapping 版本和分析器写入索引构建清单。

优先复用同素材、同模型指纹、同 textHash 的已有向量。只改名称或标签时更新词法字段，描述未变的块无需重新调用 embedding；全量重建可从兼容旧构建复用向量。模型身份或维度不一致时禁止复用。向量缓存先限定为素材自身，首版不建立跨用户共享缓存服务。

当前线上旧索引未保存模型指纹或分块版本，search_index_state 的 content_hash 也全为空。因此本次 v1→v2 迁移默认重新生成 embedding；只有能补齐可核验的历史模型身份和文本一致性依据时，才启用旧向量复用。复用机制主要保障后续 v2 增量更新和可验证的构建之间迁移，不把“都是 1024 维”当作兼容证明。

所有新向量准备和校验完成后，单次替换整个素材文档；取消 v2 的先 delete_by_query 再 bulk 写块流程。embedding 失败时保留旧的完整可搜索版本，并在状态中暴露更新滞后。新素材在首次完整版本写入成功前不能被内容召回。

共享索引状态增加每素材递增 sourceRevision。相关内容变更与入队在同一 MySQL 事务内更新 revision；worker 读取一致快照，作业固定 revision 与目标构建。ES 使用严格 external version 写入，旧 revision 不能覆盖新版本。相同 revision 的重试需比对版本与内容指纹后确认幂等成功，不直接忽略所有冲突。[Elastic 8.11 Index API](https://www.elastic.co/guide/en/elasticsearch/reference/8.11/docs-index_.html)

删除使用更高 revision 的删除标记文档，并在所有检索中排除 deleted；确认旧作业不会再写回后才能物理清理。MySQL 删除状态仍然是返回前的最终约束。删除标记与构建任务不得依赖已被级联删除的索引状态才能判断新旧。

扩展 search_index_state 的版本信息，并为每个 indexBuildId 单独记录成功 revision、contentHash、状态和错误。旧索引成功不能代表新索引也已完成。并发限流、批量文本数量、总 token 预算及超时独立配置，记录 Web 与 worker 各进程的合计服务压力。

**召回与融合策略**

1. 保留 MySQL 的同步范围筛选。引擎将同一 allowedAssetIds 应用于所有检索路；返回后仓储继续核对最新状态。首版不把权限规则改成依赖异步 ES 元数据。

现有 ID 方案的容量边界需要显式检查。ES terms 默认最多 65,536 项；超过配置容量时返回明确错误和监控指标，禁止截断候选 ID 或移除过滤。本轮不通过镜像权限字段扩大这一边界，容量扩展作为独立后续任务。[Elastic 8.11 terms query](https://www.elastic.co/guide/en/elasticsearch/reference/8.11/query-dsl-terms-query.html)

2. 查询只做空白、Unicode 和重复词等保守规范化，保留数字、否定词、实体和原始语序。沿用 query 与 keywords 的合并语义；不加入 LLM 查询改写。原始查询和模型输入的关系必须可追踪。

3. 语义路对 chunks.embedding 执行 nested kNN，按不同素材返回候选，并保留最近块的原始余弦分数与证据。初始实验窗口为 100 个素材、num_candidates 为 200；在 50/100/200 素材窗口和不同 num_candidates 下测量收益与延迟。

4. 词法路同时覆盖描述摘要与独立元数据字段。摘要使用 nested 查询并取最高块分数，避免摘要数量多的素材通过重复文本累加占便宜；名称和标签保留精确匹配能力。元数据与文本分支先合成为一条素材级词法排名，不让同一素材在 RRF 中因多字段重复出现而多次获益。首版分析器保持 standard，避免把分块、融合和分词器变化混在一起。[Elastic 8.11 nested query](https://www.elastic.co/guide/en/elasticsearch/reference/8.11/query-dsl-nested-query.html)

5. 阈值和词法门槛通过离线对照确定。旧 0.705 / 22.25 仅作为 v1 基线，不能直接继承为新索引最佳值。语义路按原始 cosine 过滤；词法路对照当前固定 min_score 与按查询分词覆盖率设置的 minimum_should_match，精确名称/标签命中单独识别。新默认必须同时满足候选覆盖和无匹配误召回门槛，不能简单删除所有阈值或把 BM25 分数伪装成概率。

6. 融合单位改成素材。两路各自对 assetId 去重并生成排名，再做等权 RRF。初版保留 k=60，减少同时调整的变量；允许同一素材的描述命中语义、标签命中词法，合并两路证据。不同块不会重复加分，重复证据也不会增加路数。名次从 1 开始时每路贡献为 (k + 1) / (2 × (k + rank))，仍落在现有 API 分数范围内。

7. 返回有序候选并标明窗口限制。默认两路各 100 个素材，融合候选最多为两路并集；引擎不根据业务 limit=1 提前缩成 1 条，也不随机选取。由于当前业务随机逻辑消费全部候选，扩大候选范围可能改变其最终分布；本轮会记录这一影响，但不借此修改业务策略或承诺配片效果。

8. 若返回前状态复核丢弃候选，可由共享仓储协调器在固定预算内扩大召回窗口并重查一次。扩窗复用查询向量、固定本次索引和配置版本，重新生成全局排名；不得为凑数降低相关性阈值、放宽作用域或无限重试。真实无候选与预算截断必须在内部诊断中区分。

9. 错误语义保持严格：embedding 不可用、ES 超时、分片失败与真实空结果不同。本轮不引入无提示的单路降级。召回按同一读索引版本执行两路请求，防止别名切换时两路落到不同构建。

每次召回记录配置/索引版本、允许素材数、两路返回数、融合后数量、复核丢弃数、扩窗次数、截断原因及 embedding/ES/数据库耗时。普通日志仅保留计数和查询指纹；原始查询、命中文本与向量只进入明确限定的离线评测或诊断数据。

**评测与验收**

先冻结 v1 代码、模型指纹、索引快照和查询集。现有合成集用于回归及快速消融，不能用来替代真实样本。实施前准备目标规模至少 500 条素材、200 条查询的独立评测样本；素材不足时全量使用，并在报告中注明限制。

查询来自两个入口各自的真实表达分布：短关键词/名称标签查询、自然语言描述、长文案分段、业务实体、近似场景干扰、无合适素材的查询、个人库和显式候选范围。查询与素材按来源视频和主题分组划分训练/调参/测试，避免同一视频切片或同句改写跨集合。测试集冻结后不再用于调参。

由业务可判读的标注给出不相关、部分相关、直接可用三个等级；标注真实画面与查询的关系，同时记录当前描述是否包含决定性信息。候选池由旧版、新版、语义单路、词法单路及人工补充共同构成；未标注候选不自动当作负例。主观或争议样本复核。

评测只到返回候选，既不模拟随机选材，也不将跨段分配成功率作为本轮验收。

| 指标 | 用途与拟定门槛 |
| --- | --- |
| Recall@20 / @50 / @100 | 主指标；v2 Recall@50 目标至少 95%，整体和两类入口分组不低于 v1 |
| Success@20 | 有相关素材的查询能否召回至少一个；显式候选范围内单独统计 |
| nDCG@10、MRR、Precision@10 | 检查融合顺序与前部噪声；不得以显著排序退化换取更多候选 |
| 无匹配误召回率 | 独立负查询上目标不高于 5%，同时不差于 v1 |
| 元数据专项 | 仅名称或人工标签包含查询词的固定用例必须命中 |
| 作用域和版本一致性 | 越界、已删除、旧版本覆盖新版本的测试违规数为 0 |
| 延迟与资源 | 同模型、同硬件、同并发比较；p95 目标不超过 v1 的 1.2 倍，同时记录 embedding/ES/MySQL 分项 |
| 入库 | 无内容变化不重复 embedding；故障不产生半套文本块；重试与乱序作业可恢复 |

95%、5% 和 1.2 倍是拟定验收目标，不是已测结果或业务 SLA。报告必须展示计数、分组指标和不确定性；样本不足或门槛冲突时，保留 v1 默认，明确记录差距，不以反复改测试集“过线”。候选标注不完备时，Recall 只对已标注相关集合成立。

消融至少比较：v1、v2 语义单路、v2 词法单路、v2 双路、去掉元数据字段、旧分块与新分块。判断增益时分别看覆盖与排序，不能只用一个 F1 数字宣布双路有效。nested 方案还必须记录索引大小、每素材块数分布和更新成本。

**实施顺序与交付**

| 阶段 | 交付内容 | 完成条件 |
| --- | --- | --- |
| P0：冻结边界与验证能力 | 两个适配层的契约用例、v1 基线、样本规范；独立 ES 8.11 测试索引验证 nested kNN/过滤/inner_hits | 确认运行集群真实版本和能力；不同素材计数、原子文档更新与延迟实验成立 |
| P1：分块与索引文档 | chunks、document、mapping 模块；来源信息、token 长度、模型指纹 | 长文本、重复摘要、多时间来源、空描述、名称/标签与模型不匹配用例通过 |
| P2：可靠索引写入 | sourceRevision、构建状态、向量复用、整素材更新、删除标记 | 失败、乱序、重试、删除与重建交叉的真实 ES/测试数据库用例通过 |
| P3：共用召回引擎 | 两路素材级召回、RRF、证据和诊断、兼容包装、有限扩窗 | 两个入口保持公开契约；白名单与排除条件生效；评分与排序可解释 |
| P4：真实样本评测 | 冻结测试集、消融报告、参数配置及索引指纹 | 质量、错误率与性能达到门槛；效果归因到索引/召回而非业务选材 |
| P5：重建与切换准备 | 新索引回填、双写追平、影子查询、核对报告、切换和回退脚本 | 可以明确证明目标构建完成，并在旧版本仍可用时切换与回退 |

P0→P1→P2→P3→P4→P5 顺序推进。P0 的兼容性或性能实验不成立时重新审查索引布局，不在业务层增加补丁绕过它。实现中按可独立验证的变更拆提交。

预计主要涉及：src/server/search 下的分块、文档、embedding、索引写入、召回和融合模块；src/server/repositories/assets.ts 的共享调用适配与索引入队；src/server/services/processing.ts 的 embed 作业；src/server/db/schema.ts 与 migration；scripts/reindex-search.ts；检索相关测试和 benchmarks/search。对业务变更函数的修改仅限索引 revision/入队钩子，不改变业务状态机。

**重建、切换与回退**

v2 使用新的物理索引和新逻辑别名，例如 asset_library_prd_recall_v2_000001 与 asset_library_prd_recall_read；dev 使用独立名称。当前 asset_library_prd 是现有索引名，不直接强行替换为同名别名。

先部署能读 v1/v2、但默认仍读 v1 的代码。建立构建清单后开启面向 v1 与指定 v2 构建的持久化双写，再按 MySQL 主键游标回填。每个作业固定目标物理索引、schema 与 sourceRevision；不得在执行时因为全局配置变化写进另一代索引。回填与实时更新通过 revision 判断新旧。

读取 MySQL 业务数据的回填只读源表；新索引的写入状态与业务状态分开记录。除资源预算外，不重新分析原视频，也不重新上传媒体。向量模型与分块内容兼容时可以复用已有向量。

回填源固定为当前 asset_entries / analysis_result_entries 和对应标签，不重新导入旧 assets 表。实测旧表 655 条 ID 已全部存在于当前模型，历史分析与索引状态也仍保留，不能混作额外素材。既有 assetId、公私归属、父子关系、审核状态和媒体 URL 生成规则全部保持。状态迁移先核对线上遗留 asset_id 列及历史行，采用兼容性增量变更，不附带删除历史列、清理主表或重跑旧素材迁移。

回填完成后核对顶层素材数、来源 revision、内容指纹、失败和滞后队列；不能用 nested 文档总数与素材数直接比较。追平增量与删除后，使用固定样本和受限影子查询比较两代结果。影子查询有独立并发预算，不进入正常响应，也不在普通日志输出原始文本和向量。

切换使用召回实现版本开关与 v2 读别名，确认读别名只指向一个构建。别名可通过一次原子操作替换目标；这保证别名变更原子性，不代替两个 HTTP 检索请求的快照固定。[Elastic 8.11 aliases](https://www.elastic.co/guide/en/elasticsearch/reference/8.11/aliases.html)

回退观察期维持两代写入，保留 v1 代码、索引和配置；出现质量、权限、延迟或索引故障时切回 v1，并核对其更新水位。观察期与旧索引清理在部署步骤中明确记录，不能回退到已经停止同步的旧数据。新旧状态核对成功之前，不清理旧索引。
