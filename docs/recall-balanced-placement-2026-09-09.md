# 语境召回与均匀分配

按用户最新要求：只使用 Embedding + Elasticsearch + RRF，两个入口的共享语义阈值设为 0.5；实际 `.env`、示例、v1 默认值和 v2 策略同步。探索中新增的 LLM 过滤代码及配置已全部移除。

查询仍以当前片段为中心，附加语境向量用于候选资格检查，防止只有孤立短语匹配就被接受。语境检查不增加第三路 RRF 分数。素材查询无片段语境时沿用单查询流程。

分段匹配按最新授权改为两阶段：

1. 每批最多 4 段收集候选，保留原素材范围和时长要求；此时不提前消耗素材，不随机截取单个结果。
2. 在候选关系中做全局分配：先最大化可匹配段数，再最小化各段中心与均匀时间目标的平方距离。同一素材最多使用一次，同一段最多一条；允许重新分配早期选择以满足后段。原随机选项仅影响同等时间方案中的素材选择。

实现：[balanced-asset-assignment.ts](../src/server/services/balanced-asset-assignment.ts)。均匀性以实际时间衡量，不能为了填空创建不存在的候选。若最多只能匹配 K 段，就按 K 个均匀目标重新求解。

## 验证

- 46 项相关测试通过，包含所有 64 个小型候选图与穷举最优解比较。
- TypeScript、定向 ESLint、diff 检查通过。
- 真实只读回放覆盖 v1 默认随机、v1 顺序和 v2 默认随机；禁止访问 chat/completions 或 responses，实际无 LLM 调用。
- 三次回放均保留 36 段原字段和时间，匹配素材均在指定列表内、时长足够，无重复素材；第 7 段“真的走到头了吗”均为空。
- 当前 v1 默认模式回放约 4.06 秒；这不是线上延迟承诺。

同一批 v1 候选的分配对照：

| 项目 | 按原顺序先到先用 | 全局均匀分配 |
| --- | --- | --- |
| 命中数 | 10 | 11 |
| 最后命中结束时间 | 30.53 秒 | 45.37 秒 |
| 最长连续命中段数 | 5 | 3 |
| 归一化时间均方误差 | 0.02237 | 0.00344 |

当前默认 v1 的命中段号：1、12、13、14、16、18、22、25、28、31、34。

## 验收边界

分配算法的均匀性与指定泛化短句回归通过，但全部语义质量尚未通过：例如 v1 第 13 段“逛街少了刷手机多了”仍选到了店铺画面。0.5 和语境向量不能保证所有候选都适合画面，分配算法只能在召回给出的候选关系中优化；均匀分布不能当作语义合格的证据。
