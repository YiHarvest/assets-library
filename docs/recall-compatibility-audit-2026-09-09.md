**线上存量素材与召回改造兼容性检查**

检查时间：2026-09-09 12:26 起，Asia/Shanghai。对象：生产 MySQL assets_library 与 Elasticsearch asset_library_prd。本报告是该时点的只读快照，后续新增、编辑和删除会改变数量。

结论：现有素材的描述、分析 JSON 和素材身份可以作为新索引的回填来源，不需要重新上传、重新分镜或重新执行视觉分析。新索引格式需要单独构建；旧向量缺少模型来源指纹，不能仅因维度相同就认定可直接复用。计划应保留描述单独入库、历史媒体路径和现有 ID 的兼容行为。

**检查方式**

使用仓库已配置的远程生产 MySQL 入口，校验配置 CA 证书链，按项目现有 VERIFY_CA 方式连接。执行 session transaction read only，并在只读事务中查询；连接返回 transaction_read_only=1、TLS_AES_256_GCM_SHA384。每条 SELECT 设置 10 秒执行上限。没有加载应用、执行启动脚本、migration、worker 或入队命令。

ES 仅执行版本、mapping、计数及查询读取；读取当前 9,745 个文档的 assetId 和 content，与 MySQL 推导的旧版分块集合逐素材比较。另检查全部文档都有 embedding，并抽查 3 条向量长度和数值有效性；没有全量下载向量，也没有调用 embedding 服务。

分析 JSON 使用当前 src/shared/contracts.ts 中的 analysisResultSchema 与锁文件对应的 Zod 4.4.3 逐条校验。校验在隔离的临时目录运行，业务 JSON 通过进程内存传递；仓库内没有写入素材原文、向量、连接串或密钥。

**需要显式兼容的存量情况**

1. 存在 1 条已完成、已发布的公共图片，没有 analysis JSON，只有 4 字符的现有描述。它已被当前 ES 正常索引。新文档构建器必须接受 analysis=null，只使用描述建索引；不能因为新增 nested 分块要求而跳过它。

2. 上述图片也没有 media_object_id 或缩略图对象引用，但保留非空 original_path。检索构建不得强制要求对象存储引用或改写媒体路径。此次未实际读取该路径对应的媒体文件，不能据此确认文件可播放或下载；该可用性问题与召回回填分开处理。

3. 有 1 条个人图片分析失败、描述为空且没有分析 JSON，当前也没有进入 ES。回填保持这一状态，不把它悄悄标记为成功；未来通过原业务重试完成后再正常入库。

4. 旧 assets 表仍保留 655 条历史记录，全部 ID 都能在当前 asset_entries 找到，历史迁移状态为 completed。analysis_results 和 search_index_state 还分别保留 654 条没有当前公私引用的历史行。回填必须读取当前 asset_entries / analysis_result_entries，不能把旧 assets 再并进来导致重复素材或覆盖。

5. search_index_state 共 2,219 行，全部状态为 done，但 content_hash 全为空。该表含当前公私素材和历史记录，不能把 2,219 当作当前可回填素材数，也不能只依赖 done 判断新构建是否完成。

6. 当前 ES mapping 不含模型指纹、模型修订、分块版本或内容哈希；抽查的 _source 也只有 assetId/content/embedding。现有 .env 写着 bge-m3 并不足以证明所有历史向量来自同一模型修订。默认迁移策略应从旧文本重新生成 embedding，并在 v2 建立来源清单；复用旧向量需要额外可核验的模型身份依据。

7. 线上 search_index_state 保留一个本地 schema 未声明的 nullable asset_id 历史列，同时已有 id/public_asset_id/private_asset_id。新状态表迁移必须与实际 SHOW/INFORMATION_SCHEMA 结果对照，采用增量兼容变更，不顺带清理该列或历史数据。公私素材表的主要内容列与当前定义相符。

**对实施计划的约束**

素材 ID、公私归属、public_asset_id 映射、父视频/分镜关系、审核状态、媒体路径与 URL 生成规则全部沿用。只构建搜索衍生数据以及所需的索引状态，不迁移素材主记录身份。

当前快照的完整回填基数为 1,563 条素材，其中 1,562 条有分析 JSON，1 条只有描述。v2 顶层文档数按素材核对，nested 文本块数按新规则另计，不能与旧版 9,745 个顶层文本块直接等量比较。实际切换前以新快照与增量水位重新核对，不能硬编码本报告的数量。

回填所需输入已经存在数据库中：描述、时间摘要、名称、标签和来源关系。重新生成 embedding 不等同于重新执行视觉分析。旧线上索引保持可读，通过新物理索引回填、增量追平和版本切换完成迁移。

本文验证的是现有数据能否支持计划中的迁移，不是新索引实现已经通过生产验证；nested 查询、写入故障恢复和迁移切换仍按 P0–P5 在隔离测试与新索引上验证。
